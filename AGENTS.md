# ChessDev — instrucciones permanentes

La especificación permanente es `docs-specification.es.md`; las decisiones posteriores en `docs/decisions.md` prevalecen cuando la modifican. El producto actual es ChessDev, plataforma de ajedrez; sustituye la experiencia de mundo virtual PixelSpace. Priorizar entrenamiento real, PGN, multijugador autoritativo y ajedrez legal comprobados con dos clientes. Mantener historial Git, URLs e infraestructura reutilizable. Core no depende del ajedrez. No crear controles falsos ni declarar pruebas no ejecutadas. No implementar pagos, Elo o IA simulados.

Acceso público obligatorio con Discord. Base de datos: Cloudflare D1, API/OAuth en Worker. El usuario exige empezar sin cargos ni facturación: no activar Blaze, Containers ni servicios pagados. Destino confirmado: Render Free para Colyseus y GitHub Pages para frontend. Cloud Run en Firebase pixelspace-93730 queda aplazado. El usuario autoriza desplegar la web una vez conectado y verificado el conjunto (docs/free-hosting.md). Nunca subir secretos, bases locales ni credenciales. Identidades de desarrollo limitadas a loopback, nunca producción. Comprobar TypeScript, lint, tests, build y E2E antes de publicar; documentar infraestructura no verificada. No delegar a subagentes sin petición explícita.

Acceso público del API a través de `https://pixelspace-world.onrender.com/api`; Render reenvía solo rutas públicas permitidas al Worker, sin mover D1 ni el secreto de Discord. Callback público en `/api/auth/discord/callback`. Esta red no alcanza workers.dev directamente; mantener el upstream del servidor en Cloudflare y no exponer `/internal` en el proxy.
